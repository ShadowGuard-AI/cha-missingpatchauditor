Two Files In, One Report Out

cha-missingpatchauditor compares installed software versions against a vulnerabilities database and reports on missing security patches.

The inputs are files the user supplies. This is not a live scan of a running machine: a baseline file and a database file go in, and a report comes out.

The repository on GitHub

Taking the Tool Aboard

git clone https://github.com/ShadowGuard-AI/cha-missingpatchauditor
cd cha-missingpatchauditor
pip install -r requirements.txt

Three steps, printed exactly, in the order given.

The Command

python3 main.py -b BASELINE -d DATABASE [-o OUTPUT]

Two required file paths and one optional output path. The brackets carry the optionality exactly as the original line carries it.

Both Paths Are Required

The baseline path and the database path are both required. Only the output path is optional.

Four Markers on the Line

-hShows the help message and exits.
-b, --baselinePath to the baseline YAML or JSON file, required. The head of this marker is painted krill pink.
-d, --databasePath to the vulnerabilities database JSON file, required. The head of this marker is painted krill pink.
-o, --outputPath to the output file, optional, and if it is not specified, output prints to stdout. This marker is left cyan.

Shapes of the Inputs

Baseline: a JSON or YAML object with a description string and a rules list. Each rule carries name, software, installed_version, required_version, and severity, where severity is high, medium, or low.

Database: a JSON list of objects, each carrying software, version, cve, and description.

The two shapes differ and are kept apart here, as they are in the source.

What the Runs Proved

A baseline with openssl installed at 1.0.0 and required at 1.1.1, plus a database row for openssl version 1.0.0, reported that missing patch with its CVE, description, and severity.

A rule already at its required version was not reported. With -o, the same JSON report was written to the named file. A missing input file exits 1, and a baseline or database that fails its schema exits 1.

Exact Match or Silence

A below required install is reported only when a database row matches its installed version as an exact string. With the database row at version 1.0.1 instead of the installed 1.0.0, the tool printed "No missing patches found." and exited 0.

A code comment adds two quieter quirks: a shorter version that prefixes the required one counts as older, and a text segment such as a prerelease tag sorts after a bare ending.
